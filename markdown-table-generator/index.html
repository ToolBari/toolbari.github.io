How Markdown tables work


A Markdown table is plain text with pipes between the cells. The first line is the header, the second line is a row of dashes that separates the header from the body, and every line after that is one row of the table. Colons in the dash row set the alignment: a colon on the left aligns left, on the right aligns right, and on both sides centres the column.


That is all there is to it — no closing tags, no special syntax. Any tool that renders Markdown turns the same text into a formatted table, which is why Markdown tables are handy for notes, documents and web pages alike.


Tips for readable tables


Keep cell text short. A table with one idea per cell is easy to scan, while long sentences inside cells make the plain text hard to follow. If a cell needs more than a few words, consider whether the information belongs in a paragraph instead.


Match alignment to content: left for words, right for numbers so the digits line up, centre for short labels. And keep the column count small — three to five columns read well on a phone, while eight columns can feel cramped.


When tables are the wrong tool


Tables suit data that compares neatly across rows and columns: prices, schedules, feature lists. They suit flowing text badly — a paragraph squeezed into a cell is hard to read in plain text and awkward on a phone.


If your content is a story, an explanation or a list of steps, use headings and paragraphs instead. Save tables for the moments when readers need to scan across and compare.


Questions people ask


How big can my table be?
Up to 10 rows and 8 columns, which keeps the table readable in plain text.


Can each column have its own alignment?
Yes. Set the alignment under each column — left, centre or right.


Does the preview match the final table?
The preview shows the same data in a real table, so what you see is what the Markdown will render as.


What if my text contains a pipe character?
Pipes are escaped automatically, so they show as text instead of splitting the cell.
