AI Token Counter (Estimator)

Paste any text to estimate its token count from two simple rules, shown as a range. You also see its word and character counts and how much of common context windows it would fill.

This tool works fully in your browser and calls no AI service, API, or backend. The count is an estimate from two rough rules, not any provider's exact tokenizer, so real token counts will differ. Treat the range as a planning guide, not a precise figure.

How the estimate works

The tool estimates tokens two ways and shows both results as a range. The first rule divides the character count by four, because a typical token is about four characters long. The second rule multiplies the word count by 1.33, because a typical word is about one and a third tokens. Real text sits somewhere between the two figures, so the range is more honest than a single number. The midpoint of the range is used for the context-window percentages.

What the range means

A narrow range means the two rules agree, which happens with plain, everyday text. A wide range usually means the text has many short words, long words, numbers, or repeated punctuation, where the two rules drift apart. For example, a text of 400 characters and 80 words gives about 100 to 107 tokens: 400 divided by 4 is 100, and 80 times 1.33 is about 107. Use the high end of the range when you need to stay safely inside a limit.

Context windows, explained

A context window is the total amount of text a model can consider at once, measured in tokens. Common window sizes are 8K (8,192 tokens), 32K (32,768 tokens), and 128K (131,072 tokens). The tool shows what share of each window your text would take, using the midpoint of the token range. A long document can fill a small window quickly, while the same text is a small share of a large one. Remember that prompts, instructions, and previous messages all count toward the same window.

Why estimates differ from real tokenizers

Real tokenizers split text into pieces using rules learned from training data, and different providers split the same text differently. Unusual words, other languages, code, and emoji can all produce more tokens than the rough rules suggest. This tool does not run any provider's tokenizer, so it cannot match their exact counts. Use it to plan and compare lengths, and check the exact count in the tool you will actually use when the number matters. If your text is close to a limit, always leave some headroom and check the final count where it will be used.

Questions people ask

What is a token?

A token is a chunk of text, roughly part of a word, that language models use as their unit of input. A common rule of thumb is about four characters per token, or about one and a third tokens per word.

Why is the count a range?

Because two rough rules are used: characters divided by 4, and words times 1.33. They rarely agree exactly, so showing both as a range is more honest than showing one number.

What is a context window?

It is the total amount of text a model can consider at once, measured in tokens. Common sizes are 8K, 32K, and 128K tokens, and prompts plus replies share the same window.

Is this the same count a provider would give?

No. Providers use their own tokenizers, which split text differently. This tool gives an estimate for planning, not an exact provider count.
