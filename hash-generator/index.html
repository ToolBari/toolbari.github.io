Hashes are fingerprints, not encryption: anyone with the same input gets the same hash. Never rely on a plain hash to protect a password.

What a hash is

A hash is a fixed-length fingerprint of some input. The same input always gives the same hash, and changing even one character gives a completely different hash. That makes hashes useful for checking whether a file or a piece of text has changed: hash it now, hash it later, and compare the two fingerprints.

Hashes are one-way. You cannot turn a hash back into the original text, and the hash does not contain the text. The only way to check a value against a hash is to hash the value again and see if the fingerprints match.

When to use each hash

MD5 gives a 32-character hash and SHA-1 a 40-character hash. Both are still common for checksums and older systems, but neither is trusted for security work any more. SHA-256 gives a 64-character hash and SHA-512 a 128-character hash, and both are the stronger choices for new work.

Use hashes to verify downloads, spot changed files, and compare records. Do not use a plain hash on its own to store a password: passwords need a dedicated slow password-hashing method, which is a different tool from this one.

Hash lengths

Each hash function produces a fixed-length result, whatever the input size. MD5 gives 32 hex characters, SHA-1 gives 40, SHA-256 gives 64, and SHA-512 gives 128, so the length of a hash tells you which function made it.

Longer hashes are not just longer, they are also harder to collide. A collision is when two different inputs produce the same hash, and with the longer SHA functions a collision is so unlikely that it can be ignored in practice.

Questions people ask

What is the difference between MD5 and SHA-256?

Both produce a fixed-length fingerprint, but SHA-256 produces a longer 64-character hash and is the stronger choice for new work, while MD5 is kept for older checksums.

Can a hash be reversed?

No. A hash is one-way: you cannot turn it back into the original text. The only way to check a value is to hash it again and compare.

Does the tool upload my file?

No. Files are read and hashed in your browser only, and nothing is sent anywhere.

Why do two files with the same text have the same hash?

A hash depends only on the bytes it is given, so identical content always gives an identical hash, whatever the file name.
