.htaccess Redirect Generator

Paste your old and new addresses, one pair per line, and get a ready .htaccess block of 301 redirects. The rules are built in your browser, so nothing is uploaded.








Always keep a backup of your .htaccess file before you change it. A wrong rule can break a site, so test each redirect after you publish it.


How to use the rules


Copy the finished block and paste it into the .htaccess file in the root folder of your Apache site. Each line is one redirect: when a visitor asks for the old path, the server answers with the new address and a 301 status, which means the move is permanent.
Keep a backup of your current .htaccess file first, so you can restore it if anything goes wrong. After publishing, open each old address in your browser and check that it lands on the new one.


Writing good pairs


Write one pair per line, with the old path first and the new address second, separated by a space. The old path must start with a forward slash and is the path on your own site, without the domain name. The new address can be a full address starting with http or https, or a path on the same site starting with a forward slash.
Lines that do not follow this format are skipped and listed below the output, while rules are still made for the lines that are correct. Note that these simple rules match the path only, not any query string on the old address.


Where the rules live


The .htaccess file sits in the top folder of a site on an Apache server, and the server reads it on every request. Redirect rules near the top of the file run first, which matters when one old address could match more than one rule.
Not every host uses Apache, so check your hosting before relying on these rules. Some servers use a different configuration file, and some hosts manage redirects through a control panel instead of a file you edit by hand.


Questions people ask


What is a 301 redirect?
A 301 redirect tells browsers and search engines that a page has moved permanently, so visitors to the old address are sent to the new one.


What format do the pairs use?
One pair per line, with the old path first and the new address second, separated by a space. The old path must start with a forward slash.


Can the new address be on another site?
Yes. Use a full address starting with http or https for another site, or a path starting with a forward slash for the same site.


What if a line is wrong?
Lines that do not follow the format are skipped and listed below the output, and rules are still made for the lines that are correct.
