What changes between JSON and YAML


JSON marks structure with braces, brackets and commas. YAML drops most of that punctuation and uses indentation instead: each level of nesting is indented two spaces further in. A JSON object becomes a set of key: value lines, and a JSON array becomes a list of lines starting with a dash.


Quotes mostly disappear too, because YAML does not need them around plain words. This converter adds quotes back only where they matter — around strings that look like numbers, that contain a colon or a hash, or that start or end with a space — so the YAML stays valid.


Tips for clean YAML


Keep the two-space indentation exactly as the converter produces it. YAML reads meaning from spacing, so one extra or missing space can move a value to the wrong level or break the file. Tabs do not work in YAML, so always use spaces.


Check the order of your keys after converting: they stay in the same order as in your JSON, which makes the YAML easy to compare with the original. If a value came out quoted and you expected plain text, it is because the text would otherwise be read as a number, a true or false value, or nothing at all.


Common mistakes to avoid


The most common YAML mistake is mixing tabs and spaces — YAML only accepts spaces, so never press Tab when editing the output by hand. The next is changing the indentation of one line and not the lines below it, which moves a value to a different level.


Watch out for strings that look like dates or numbers, such as version codes. This converter quotes them automatically, so a value like 2.10 stays text instead of becoming a number.


Questions people ask

Yes. Keys appear in the YAML in the same order as in your JSON.
