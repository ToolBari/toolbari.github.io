    The parts of a URL

    A web address is built from parts, each with its own job. Take https://example.com:8080/docs/guide?lang=en#top. The scheme is https, the host is example.com, and the port is 8080. The path is /docs/guide, which names the resource on that host. The query is lang=en, and the fragment is top.

    The scheme says how the address should be fetched, and the host says where. The port is usually left out, in which case the usual port for the scheme is used. The path can have many segments separated by slashes. The query carries extra data, and the fragment points to a part of the page rather than a different page.

    Reading query parameters

    The query is a list of key and value pairs after the question mark, separated by ampersands, such as lang=en&page=2. Values are percent-encoded when they contain characters that are not allowed in an address: a space becomes %20, and an ampersand inside a value becomes %26. This parser decodes each value so you can read it as plain text.

    A key can appear more than once in a query, and each appearance is listed separately here. Tracking links often carry several parameters at once, which is why a shared link can look so long. Reading the decoded list shows exactly what the link is carrying.

    Questions people ask

    What is the difference between the path and the query?

    The path comes right after the host and names the resource, such as /docs/guide. The query starts with a question mark and carries extra data as key and value pairs, such as lang=en. The fragment starts with a hash and points to a part of the page.

    Why do some characters show as percent codes?

    Addresses may only contain a limited set of characters, so others are written as a percent sign followed by two hexadecimal digits. For example, a space becomes %20 and an ampersand becomes %26. This parser decodes those values back for you.

    Can I paste a link without https at the start?

    Yes. If you paste an address such as example.com/page, the parser tries it with https added. If it still cannot be read as an address, it will say so instead of guessing.

    Does the parser open or check the link?

    No. Everything happens in your browser from the text you paste. The parser never sends the address anywhere and never checks whether the page exists.
