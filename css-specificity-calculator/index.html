This calculator follows the standard specificity rules for IDs, classes, attributes, pseudo-classes, elements and pseudo-elements. How specificity is scored

Every CSS selector has a specificity score made of three numbers, written (a, b, c). The first number counts ID selectors such as #header. The second counts class selectors such as .menu, attribute selectors such as [type="text"], and pseudo-classes such as :hover. The third counts type selectors such as div and pseudo-elements such as ::before. Combinators, commas and the universal selector * add nothing.

Scores are compared from left to right. A selector with a higher first number wins, whatever the other numbers are, which is why one ID beats any number of classes. If the first numbers are equal, the second numbers decide, and then the third. The pseudo-class :not() adds nothing itself, but the selector inside it counts as normal. The pseudo-class :where() is different: it and everything inside it add nothing at all.

How to use the comparison

Type a selector in the first box and press the button to see its score with a breakdown of what was counted. Type a second selector to compare the two: the tool shows both scores and says which selector wins, or that the scores are tied. When two selectors tie, the rule that appears later in the stylesheet wins.

Keeping specificity low makes stylesheets easier to manage. Prefer classes over IDs for styling, avoid long chains of selectors, and reach for a more specific selector only when you need to override something on purpose. If a style refuses to apply, comparing the two competing selectors here usually shows why.

Questions people ask

What does (a, b, c) mean in CSS specificity?

The three numbers count different kinds of selector parts. The first counts ID selectors, the second counts class selectors, attribute selectors and pseudo-classes, and the third counts type selectors and pseudo-elements. A selector with a higher first number always wins, whatever the other numbers are.

Does :not() add to specificity?

The :not() pseudo-class itself adds nothing, but the selector inside it does count. So :not(.active) scores the same as .active, which is (0, 1, 0). The :where() pseudo-class is different: it and everything inside it add nothing at all.

Why does an ID beat any number of classes?

Specificity is compared number by number from left to right, not added up into one total. One ID gives a score starting with 1, and no count of classes can raise the first number, so the ID selector always wins against selectors with no ID.

What happens when two selectors have the same score?

When the scores are equal, the rule that appears later in the stylesheet wins. Inline styles and declarations marked important sit outside this scoring and can change the result.
