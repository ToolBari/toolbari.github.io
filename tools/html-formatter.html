What an HTML formatter does

HTML is the language that builds web pages, and it is written with tags: opening tags like a division tag, closing tags that end a block, and text in between. When HTML is written by hand, it usually looks tidy, with each tag on its own line and the tags inside other tags pushed in a little to show the structure. When HTML is copied from a page, generated by a tool, or squeezed into one long line to save space, that tidy shape is gone, and what is left is a wall of code that is hard to read and hard to fix.

A formatter takes that messy HTML and arranges it neatly. It puts each tag on its own line. It indents the tags that sit inside other tags, two spaces per level, so you can see the shape of the page at a glance: this list sits inside this division, these list items sit inside the list, this paragraph is a child of that division. Nothing about the meaning changes. The tags stay the same, the words stay the same, and the page looks exactly the same in a browser. Only the spacing changes, and that spacing is what makes the code readable to a human.

That readability is the whole point. When you can see the structure, you can find the tag you need to change, spot where a block starts and ends, and understand a page you did not write. When the code is one long line, even a small change means hunting through a wall of text. Formatting turns a wall back into a building with visible rooms and doors.

The formatter on this page works entirely in your browser. Your code never leaves your device, which matters when you are working with a page that belongs to someone else or contains private text. There is no signup, no upload and no limit on how much you format.

How to use the formatter

Start by pasting your HTML into the box at the top of the tool. On a desktop computer, click into the box and paste with the keyboard. On a phone, long-press inside the box and choose Paste from the menu that appears. Then tap the Format HTML button. The clean version appears in the result box below, ready to copy with the Copy result button.

If you are not sure what to paste, tap the Load an example button. It fills the box with a small messy block of HTML so you can see what the formatter does before you trust it with your own code. Format the example, read the result, and then clear the box and paste your own code in its place.

Next to the Format button are two mode buttons: Formatted and Minified. Formatted is the default, and it gives you the clean indented code described above. Minified gives you the smallest version instead: the same tags and text with the indentation and the line breaks between tags removed, so the whole block takes up as little space as possible. Tap either mode button and the result updates at once, so you can compare the two and copy whichever one you need.

The result box is a plain text box, which means you can tap into it, select the text and copy it yourself if you prefer, or use the Copy result button to copy the whole thing in one tap. On a phone, the copy button is the easier route, because selecting a long block of text by hand is fiddly on a small screen.

Worked example: one messy block, before and after

Here is a small block of HTML as it often arrives: everything squeezed onto one line, with no spaces to show where one tag ends and the next begins.

<div><p>Hello</p><ul><li>First</li><li>Second</li></ul></div>

That block is only ten tags, and it is already hard to read. Now here is the same block after formatting, exactly as this page produces it.

<div>
  <p>
    Hello
  </p>
  <ul>
    <li>
      First
    </li>
    <li>
      Second
    </li>
  </ul>
</div>

Three things changed, and only three. First, every tag moved onto its own line, so you can point at any tag and see it whole. Second, the tags inside other tags were indented two spaces per level: the paragraph and the list sit one level inside the division, the list items sit one level inside the list, and the words sit one level inside their tags. Third, nothing else changed at all: the tags, the words and the order are exactly the same as before.

Notice what the formatter did with the empty elements in a longer block. Tags that never have a closing tag, such as a line break, an image, an input field, a horizontal rule, and the head tags for page data and style links, are left exactly as they are. The formatter never invents a closing tag for them, and it never indents the tags that follow them as if they were children. That is important, because a closing tag on a line break would be wrong code, and wrong indentation would make the structure look deeper than it really is.

The same block, minified, goes back to a single line with the spaces between tags removed. It is the same code in a smaller package, and it is the version you would use when the file needs to be as small as possible rather than as readable as possible.

Formatted or minified: which one do you need?

Use the formatted version whenever a human needs to read or change the code. That means when you are learning, when you are fixing a bug, when you are handing code to someone else, and when you are coming back to a page you wrote months ago and no longer remember. Readable code is code you can trust, because you can see what it does.

Use the minified version when the file needs to be small and nobody needs to read it. A minified file downloads faster, which matters on a slow connection or a phone, and it takes up less space on a server. The page looks the same in a browser either way, because browsers do not care about indentation. They read the tags, not the spaces.

The golden rule is to keep both. Keep the formatted version as your working copy, the one you edit, and make a minified copy only when you publish. If you minify your only copy, you still have the code, but you have lost the readable shape of it, and the next time you need to change something you will be reading a single long line again. Formatting can rebuild the shape from a minified file, so the loss is not permanent, but it is a needless round trip.

Common mistakes

The most common mistake is formatting minified code and expecting the comments back. When code is minified, the comments are removed, and they are gone for good. A formatter rebuilds the indentation, but it cannot rebuild words that no longer exist in the file. If the comments mattered, they live only in the original file, which is one more reason to keep a readable copy of everything you publish.

The second common mistake is pasting a whole page, including its scripts, and expecting the script code to be formatted too. This formatter arranges HTML tags. The words inside a script block are JavaScript, not HTML, and the formatter treats them as plain text: it does not indent the lines of a script or tidy the code inside it. If you need to tidy JavaScript, use a JavaScript tool instead, and keep your HTML and your scripts in separate steps.

The third common mistake is expecting formatting to fix a page that looks wrong. Formatting changes spacing, and spacing between tags does not change how a browser shows a page. If a page looks wrong, the cause is in the tags themselves: a missing closing tag, a tag closed in the wrong order, or a style rule doing something unexpected. Formatting can help you find the problem, because a neatly indented page makes a missing tag easier to spot, but it cannot fix the problem for you.

The fourth common mistake is forgetting to copy the result before closing the tab. The formatter does not save anything. When you close the page, your code is gone, which is by design: nothing leaves your device. Copy the result into your own file as soon as you are happy with it.

What it cannot do

Formatting arranges your code neatly. It does not fix broken tags or missing closing tags. If a tag is missing its closing partner, the formatter will indent everything after it as if it were inside that tag, because it can only follow the structure it is given. The result will look odd, and that oddness is a useful clue: it tells you where the missing tag probably is. Fix the tag, then format again.

The formatter does not check whether your HTML is valid, and it does not add tags that are missing. It does not understand stylesheets or scripts, and it does not change the meaning of your code in any way. It also cannot recover anything that was removed before you pasted the code in: comments, extra attributes and whitespace inside text are all gone once they are gone.

What it does, and does well, is one job: take HTML that is hard to read and return the same HTML in a shape that a human can read. For that job, and for the matching minify job when you need the smallest file, it is all you need, and it does it without sending your code anywhere.

Questions people ask

Is this HTML formatter free?

Yes. You can format as much HTML as you like, free, with no signup and no download.

Does my code leave my device?

No. The formatting happens in your browser on your own device. Nothing is uploaded to a server and nothing is saved.

Will formatting fix broken HTML?

No. Formatting only changes the spacing. It does not fix broken tags or missing closing tags, though the neat indentation often makes a missing tag easier to spot.

What is the difference between formatting and minifying?

Formatting adds indentation and line breaks so a human can read the code. Minifying removes them so the file is as small as possible. The tags and the words stay the same either way.

Can I format a whole web page?

Yes. Paste the whole page and the formatter will indent every tag. Keep in mind that script code inside the page is treated as plain text and is not formatted as code.

Does it work on my phone?

Yes. Paste with a long press, tap the Format button, and copy the result with one tap. The buttons and boxes are sized for touch.
