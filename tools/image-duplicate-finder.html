How to use the duplicate checker

Tap the file box and pick the photos you want to check — you can pick many at once, from one folder or several. Then tap Find duplicates. The page reads each file on your device, works out its SHA-256 hash (a long fingerprint that is unique to the file's exact contents), and groups the files that share the same hash. Each group is a set of exact duplicates: files with byte-for-byte identical content. If no two files match, the page says so honestly: no exact duplicates found among the files you picked.

The results show each group with the file names and sizes, so you can see which copies you have and where they are. Nothing is deleted and nothing is changed — the page only shows you what it found, and the decision about what to keep is yours. Use the copy button to copy the result as text if you want a list to work through later.

Everything happens on your device. The files are never uploaded to any server, never sent anywhere and never stored. The page has no account, no sign-up and no network step at all — you can use it with no connection once it has loaded. That matters for photos, which are personal, and it is why the checker is built this way.

What counts as an exact duplicate

An exact duplicate is a file with identical content — every byte the same. Two copies of the same photo, made by copying the file, are exact duplicates even if they have different names and sit in different folders. The hash does not care about the name, the folder or the date: it only cares about the contents. If the contents match, the hash matches, and the page groups them.

But a photo that has been changed in any way is not an exact duplicate, even if it looks identical to your eye. A resized copy is a different file. A copy saved at a different quality setting is a different file. A copy that has been rotated, cropped, or had its metadata edited is a different file. Even opening a photo in an editor and saving it without changing anything can rewrite the file and change its hash. The checker is strict by design: it only reports true copies, so a group it shows you is a group you can trust.

That strictness is also the checker's limit, and it is worth understanding before you use it. If you have the same photo in three sizes — the original, a web-sized copy and a thumbnail — the checker will not group them, because their contents differ. Those are near-duplicates, and they need a different kind of tool, covered in the section below.

Why duplicates pile up

Duplicates pile up quietly, a few at a time, until they take real space. The most common cause is copying: a photo copied from a camera to a computer, then copied again into a backup folder, then copied again into a shared album, is three files with the same content. Downloads do the same — the same photo downloaded twice, once from a message and once from an email, sits in two places with two names.

Backups are the second cause. A backup that copies a whole folder, then a second backup that copies it again under a new name, doubles everything in it. That is not a bad thing — backups are supposed to be copies — but it means a duplicate check across your whole device will find your backups too, and you should not delete those. The checker's job is to show you the groups; your job is to know which copies are backups and which are clutter.

The third cause is burst shots and repeated shots. A camera set to burst mode takes many photos that look nearly identical, but they are not exact duplicates — each is a separate file with different contents. The checker will not group them, and that is correct: they are different photos, even if they look the same. Only true file copies appear in the results.

Near-duplicates: the photos this page cannot find

Near-duplicates are photos that look the same or nearly the same but have different file contents: the same photo at two sizes, the same photo saved at two quality settings, the same scene shot twice a second apart, or a photo and its edited version. Finding them needs a tool that compares what photos look like, not what their bytes are — and that is a different job from hashing.

Two free tools do that job well. dupeGuru, at dupeguru.com, is a free desktop program that finds duplicate and similar files, including pictures that match by content rather than by exact bytes. Czkawka, at github.com/qarmin/czkawka, is a free and open-source tool that finds similar images as well as exact duplicates, and it runs on the main desktop systems. Both work on your own computer, on your own files, and both are free.

The honest way to use them is in two passes: first this page, to find the exact duplicates with certainty, and then one of those tools, to find the near-duplicates by similarity. The second pass needs more care, because a similarity match is a judgement, not a certainty — two photos that look alike may still be different shots you want to keep. Check each group before you delete anything.

How the check works

The checker uses SHA-256, a standard hash function. A hash function takes any file, of any size, and produces a fixed-length fingerprint — 64 hexadecimal characters — that is unique to that file's exact contents in practice. Change one byte and the fingerprint changes completely. Two files with the same fingerprint have the same contents, with a certainty so high that it is treated as a fact.

The hashing runs in your browser, on your device, using the built-in cryptography of the browser itself. The page reads each file you pick, hashes it, and compares the fingerprints. No file is uploaded, no hash is sent anywhere, and no record is kept after you leave the page. The steps shown under the result list how many files were checked and how many groups were found, so you can see the scale of the check.

Large files take a little longer, because the whole file must be read to hash it. A folder of a few hundred photos takes seconds; a folder of thousands takes longer, and the page will look busy while it works. That is normal — the work is the reading, and the reading is what makes the answer trustworthy. A checker that answered instantly would be guessing.

What to do with the duplicates you find

First, do not delete anything in a hurry. A duplicate group is a fact about your files, not an instruction. Before you delete a copy, check that it really is a copy you do not need: open it, compare it with the one you plan to keep, and make sure the keeper is the better version — the original, the full-size one, the one with the metadata intact. In a group of three, keep the best one and remove the other two, not the first one you happen to click.

Second, remember your backups. A duplicate found across two folders may be your backup doing its job. If one copy lives in your backup folder and the other in your working folder, both are doing useful work, and deleting the backup copy defeats the purpose of having a backup. The clutter worth removing is the accidental copy: the same photo downloaded twice, or copied into a folder and forgotten.

Third, make a backup before a big clean-up, if you do not already have one. Copy the folder to an external drive or a second location, then delete the duplicates. That way a mistake costs you nothing: the copy is there to restore from. And work through the groups one at a time rather than deleting in bulk — a careful hour beats a fast mistake.

What this page cannot do

This page cannot find near-duplicates — photos that look the same but have different contents. It cannot compare photos by what they show, only by their exact bytes. It cannot check photos it cannot see: it only checks the files you pick, so it will not scan your whole device or find duplicates in folders you did not include. And it cannot tell you which copy to keep — that needs your judgement about which version is the original, which is the best quality, and which is a backup worth keeping.

It also cannot delete anything. That is deliberate: a page that deletes your photos would be a dangerous thing, and no automatic choice should make that decision for you. The checker shows you the groups, and you decide. The honest result is the list; the rest is yours.

Questions people ask

What is an exact duplicate?

An exact duplicate is a file with byte-for-byte identical content. Two copies of the same photo, made by copying the file, are exact duplicates even if they have different names and sit in different folders. This page matches them by their SHA-256 hash, a fingerprint of the file's exact contents.

Will it find photos that look the same but are different files?

No. A resized copy, a re-saved copy or an edited version has different contents, so its hash differs and this page will not group it. Those are near-duplicates, and they need a similarity tool — the guide on this page names two free ones, dupeGuru and Czkawka, that compare photos by what they look like.

Are my photos uploaded anywhere?

No. The checker hashes your files on your device, in your browser, and nothing is sent to any server. There is no upload, no account and no copy kept anywhere. The page works with no network connection at all once it has loaded.

How many files can I check at once?

There is no fixed limit in the page, but large batches take longer because every file must be read to hash it. A few hundred photos take seconds; thousands take longer. If the page looks busy, it is working — let it finish rather than tapping the button again.

What should I do with the duplicates I find?

Check each group before you delete anything, and keep the best copy — the original, the full-size one, the one with its metadata intact. Remember that a copy in a backup folder is doing useful work. Make a backup before a big clean-up, and work through the groups one at a time.

Why do two copies of the same photo have different file sizes?

Because one of them has been changed: resized, re-saved at a different quality, rotated, cropped, or stripped of metadata. Any of those changes rewrites the file and changes its size and its hash. The two files look the same but their contents differ, so they are near-duplicates, not exact duplicates.
