JSON Diff Checker

Paste two JSON documents and compare them key by key. The tool lists added, removed and changed keys with their full paths and old and new values, ignoring key order and whitespace.

This checker compares JSON structure and values, not plain text. Two documents with the same keys and values in a different order count as equal, and formatting differences are ignored. It works on text you paste here — it cannot open or compare files.

How the comparison works

Paste the two JSON documents into the boxes and press Compare. The tool parses both sides, then walks through every key. For each key it checks whether the key exists on both sides and whether the values match. Keys are compared by name, not by position, so a different key order does not count as a difference, and extra spaces or line breaks are ignored too.

Nested objects are compared the same way, one level at a time. A difference deep inside a document is reported with its full path in dot notation, for example user.address.city, so you can find it at once. Arrays are compared element by element, with the position shown in brackets, for example items[2].

Reading the results

The results are grouped into three lists. Changed keys show the old value and the new value side by side. Removed keys were in the left document but not in the right one, and added keys were in the right document but not in the left one. Keys that match on both sides are counted as unchanged, and if nothing differs at all the tool says the two documents are identical.

If one side is not valid JSON, the tool names the side that failed and shows the parser's error message, so you can fix the exact problem. Nothing is compared until both sides parse cleanly.

Questions people ask

Does key order matter in the comparison?

No. The comparison ignores key order and whitespace, so two documents with the same keys and values in a different order count as equal. Only real differences in keys or values are reported.

What happens if my JSON is not valid?

The tool shows a plain message naming which side failed, left or right, together with the parser's error message, so you can find and fix the problem. Nothing is compared until both sides are valid JSON.

How are nested keys shown?

Nested keys are shown with their full path in dot notation, for example user.address.city, so you can see exactly where a difference sits inside a larger document. Array items are shown with their position in brackets, for example items[2].

Does the tool send my JSON anywhere?

No. The comparison runs entirely in your browser, and nothing you paste is sent anywhere. You can compare private data without it leaving your device.
